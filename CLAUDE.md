# Конверкот — правила проекта

## Что это
Local-first PWA для личных финансов: бюджет «план–факт», финансовые цели с расчётом взносов,
финансовый резерв, баланс семьи, настраиваемый дашборд из виджетов. Полное ТЗ — docs/PLAN.md.
Раздел 5 PLAN.md (формулы и тестовые векторы) — единственный источник истины для расчётов.

## Стек (не добавляй зависимости вне списка без согласования)
TypeScript strict, Vite, React 18, React Router, Tailwind CSS, shadcn/ui, Recharts, dnd-kit,
Dexie + dexie-react-hooks, Zod, date-fns (локаль ru), PapaParse, ExcelJS (только dynamic import),
pdfmake (только dynamic import, этап 8), vite-plugin-pwa (registerType: 'prompt'),
Vitest, Testing Library, fake-indexeddb, Playwright. ESLint + Prettier.

## Команды
- npm run dev — разработка
- npm run build — сборка
- npm run lint / npm run typecheck / npm test / npm run e2e
Перед тем как считать задачу выполненной, прогони lint, typecheck, test (и e2e, если менялся UI-сценарий).

## Архитектура
- src/core — чистые функции. Не импортирует React, Dexie, src/db, src/features.
- src/db — схема Dexie, миграции, репозитории. UI обращается к данным только через репозитории.
- src/features/<вкладка> — экраны. src/features/overview/widgets — виджеты дашборда и registry.ts.
- src/components — общие компоненты. src/lib — утилиты.

## Жёсткие правила
- Деньги — целые копейки (amountMinor, integer). Никаких float для хранимых сумм.
  Прогнозы считаются в number и округляются Math.round до копеек только при сохранении/выводе.
- Месячная ставка i = r / 12. Инфляция: (1 + π)^(месяцы / 12). Взнос — платёж в конце месяца,
  стартовые накопления S растут по ставке i. Срок при заданном взносе — линейный перебор 1..1200,
  НЕ бинарный поиск.
- Переводы (transfer), корректировки (adjustment) и переоценки (revaluation) не входят в доходы,
  расходы и свободный остаток. Взнос в цель — перевод + конверт (Envelope), не расход.
- Остаток счёта не хранится — вычисляется из openingBalance и операций.
- Сумма конвертов по счёту ≤ остаток счёта. Конверт — только на счёте с деньгами (не недвижимость, авто, доля в бизнесе).
  Резерв = ликвидные счета − конверты других целей на ликвидных счетах.
- Остаток счёта задан на начало openingDate: операции раньше этой даты остаток не меняют.
- Тип бюджета, кредитная нагрузка и распределение по целям — по «обычному месяцу» (среднее полных месяцев,
  иначе план), а не по текущему месяцу: вывод не должен зависеть от числа. Из свободных денег сначала
  вычитается основной долг по графику, резерв ниже нормы получает деньги первым.
- Приоритет цели: меньше = важнее; цель «резерв» всегда 0.
- Даты операций — строки YYYY-MM-DD, месяцы — YYYY-MM, без часовых поясов.
- Нормативы (лимиты вычетов, ставки НДФЛ, лимит страхования вкладов) — только в src/core/rules/<год>.ts
  с полями source (URL) и checkedAt. Не хардкодить в компонентах.
- Никаких рекомендаций конкретных ценных бумаг, фондов, брокеров. Только классы активов.
  Дисклеймер: «Расчёты носят информационный характер и не являются индивидуальной инвестиционной рекомендацией».
- Никаких счётчиков аналитики и сторонних скриптов. Финансовые данные не покидают устройство.
  Единственное исключение — виджет «Новости»: читает ленту по адресу, который задал пользователь,
  только при явно включённой настройке externalFeedsEnabled (по умолчанию выключена).
- Код, идентификаторы, коммиты — на английском. Весь текст интерфейса — на русском, простым языком,
  без жаргона; строки держать в src/i18n/ru.ts.
- Каждый виджет дашборда обёрнут в Error Boundary и имеет «пустое состояние».
- Мобильная ширина 375 px: без горизонтальной прокрутки.

## Как работать
- Работай строго в рамках текущего этапа из docs/PLAN.md. Не забегай вперёд.
- src/core — через TDD: сначала тесты с векторами из раздела 5, потом реализация.
- Если формула в плане кажется неверной или требования противоречат друг другу — остановись и спроси,
  не «исправляй» молча.
- Небольшие логичные коммиты (Conventional Commits).
- В конце этапа обновляй документы: CHANGELOG.md (новая версия + строка в сводной таблице),
  STRUCTURE.md (новые файлы и статистика), STACK.md (если менялись зависимости или команды),
  README.md (состояние этапов). Версия приложения живёт в package.json.
- В конце этапа: чек-лист «Готово, когда» с отметкой по каждому пункту, как проверено,
  что осталось/отложено, какие решения принял сам.
