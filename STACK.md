| Сторона вкладок на телефоне                      | `localStorage`, ключ `konvert-me.hand`    | `right` или `left`; не в копии и не стирается с данными |

## Внешние запросы

По умолчанию приложение **не делает ни одного запроса наружу**: ни
аналитики, ни сторонних скриптов, ни шрифтов с чужих доменов.

Единственное исключение — виджет «Новости»: он читает ленту по адресу,
который ввёл пользователь, и только после включения настройки «Разрешить
запрашивать ленты новостей». Запрос уходит без cookies и без referrer,
API-ключ (если задан) отправляется только на хост этой ленты.

Статистика пилота никуда не отправляется: пользователь сам копирует текст из
«Настроек» и вставляет в анкету. Ссылка на анкету открывается только по нажатию.

Обновления: пока приложение открыто, оно раз в час и при возвращении на экран
запрашивает на том же сайте скрипт service worker (без кэша) и, если сайт
ответил, просит браузер проверить обновление; когда оно ждёт, читает
`/version.json` (версия и заметки, не в офлайн-кэше). Данных в запросах нет.

Письмо о проблеме (значок жука) не отправляется приложением: ссылка `mailto:`
открывает почту человека с текстом и технической информацией, которую он видит
до отправки.

## Команды

```bash
npm install          # установка зависимостей
npm run dev          # дев-сервер (http://localhost:5173)
npm run build        # проверка типов + production-сборка
npm run preview      # локальный просмотр собранного приложения

npm run lint         # ESLint, предупреждения запрещены
npm run typecheck    # tsc -b
npm test             # модульные тесты (Vitest)
npm run coverage     # тесты с покрытием: ядро — порог 95 %
npm run e2e          # Playwright: сам собирает проект и поднимает preview
npm run format       # Prettier

npm run icons        # перерисовать иконки из src/components/brand/cat-mark.ts
npm run og-image     # перерисовать картинку превью ссылки (public/og-image.png)

npm run deploy       # опубликовать сайт на GitVerse Pages (только из коммита)
npm run deploy -- --dry-run  # собрать и подготовить файлы сайта, ничего не отправляя
```

Перед первым запуском e2e: `npx playwright install chromium`.

## Качество

| Показатель                       | Значение                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------- |
| Модульных тестов                 | 713                                                                                         |
| E2E-прогонов                     | 201 = 98 сценариев × два проекта (1280 и 375 px) + 4 проверки доступности + скорость        |
| Покрытие `src/core`              | 100 % строк при пороге 95 %                                                                 |
| Покрытие всего проверяемого кода | 97,9 % строк                                                                                |
| Начальный JS                     | ~269 КБ gzip при лимите плана 300 КБ (лендинг и политика вошли в основной кусок)            |
| Отдельные куски                  | графики 103 КБ, мастер импорта 12 КБ, ExcelJS 256 КБ — по требованию                        |
| PDF финплана                     | pdfmake 346 КБ и шрифт Roboto 469 КБ — по нажатию, лежат в офлайн-кэше                      |
| 10 000 операций: «Бюджет»        | открывается за 121–241 мс при лимите 500 мс                                                 |
| 10 000 операций: «Обзор»         | пересчитывается за 149–182 мс при лимите 500 мс                                             |
| Доступность                      | WCAG AA по контрасту, Tab и видимый фокус, подписи — все экраны, лендинг и политика, 2 темы |

Размеры — из отчёта сборки Vite (`gzip:`); сторонний `gzip -c` даёт на пару
килобайт меньше из-за другого уровня сжатия.

Скорость меряет `e2e/performance.spec.ts`: три года операций заходят через
резервную копию, время идёт внутри страницы от нажатия до кадра с результатом,
пять замеров, в лимит должен уложиться самый долгий. Проект `performance`
запускается после остальных, чтобы не мерить загруженную машину. Цифры выше —
с машины разработки; с замедлением процессора в 4 раза (DevTools) самые долгие
замеры были 424 мс у «Бюджета» (первое открытие) и 300 мс у «Обзора».

Доступность проверяет `e2e/accessibility.spec.ts` без сторонних библиотек:
подписи — по дереву доступности Chromium, контраст — по формуле WCAG 2.1 над
цветами, которые рисует страница (OKLCH переводится в sRGB через canvas),
клавиатура — обходом по Tab с проверкой рамки или обводки фокуса. Проверка тяжёлая, поэтому это
отдельный проект Playwright: он идёт после сценариев и сам проходит обе ширины, а
замер скорости — после него.
