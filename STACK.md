## Хранение данных

| Что                                              | Где                                     | Комментарий                                            |
| ------------------------------------------------ | --------------------------------------- | ------------------------------------------------------ |
| Финансы (счета, операции, цели, планы, конверты) | IndexedDB, база `konvert-me`            | Схема v6, доступ только через репозитории              |
| Источники дохода, полисы, импорты                | Та же база: `incomeSources`, `policies` | Импорт помечает операции `importBatchId`               |
| Настройки приложения                             | Та же база, таблица `settings`          | Одна строка `app`; какие напоминания скрыты и когда    |
| Раскладка «Обзора»                               | Та же база, таблица `dashboardLayouts`  | Порядок и размеры виджетов                             |
| Закладки и ленты новостей                        | Таблицы `links`, `feeds`, `feedItems`   | Ключи API — на устройстве, в ошибки не попадают        |
| Вычеты по годам                                  | Таблица `deductionYears`, ключ — год    | Доход, расходы, дети, жильё, продажа, бумаги, статус   |
| Чеки и договоры                                  | `documents` и `documentFiles`           | Описание отдельно от байтов; до 10 МБ на файл          |
| Финансовый план                                  | Таблица `financialPlans`, одна строка   | Расчёты образования и пенсии, риск, заметки, пересмотр |
| Тема оформления                                  | `localStorage`, ключ `konvert-me.theme` | Тёмная по умолчанию, применяется до первой отрисовки   |
| Резервная копия                                  | JSON-файл у пользователя                | Вместе с файлами документов (base64); AES-GCM + PBKDF2 |

## Внешние запросы

По умолчанию приложение **не делает ни одного запроса наружу**: ни
аналитики, ни сторонних скриптов, ни шрифтов с чужих доменов.

Единственное исключение — виджет «Новости»: он читает ленту по адресу,
который ввёл пользователь, и только после включения настройки «Разрешить
запрашивать ленты новостей». Запрос уходит без cookies и без referrer,
API-ключ (если задан) отправляется только на хост этой ленты.

## Команды

```bash
npm install          # установка зависимостей
npm run dev          # дев-сервер (http://localhost:5173)
npm run build        # проверка типов + production-сборка
npm run preview      # локальный просмотр собранного приложения

npm run lint         # ESLint, предупреждения запрещены
npm run typecheck    # tsc -b
npm test             # модульные тесты (Vitest)
npm run coverage     # тесты с покрытием: ядро — порог 95 %
npm run e2e          # Playwright: сам собирает проект и поднимает preview
npm run format       # Prettier

npm run icons        # перерисовать иконки из src/components/brand/cat-mark.ts
```

Перед первым запуском e2e: `npx playwright install chromium`.

## Качество

| Показатель                       | Значение                                                               |
| -------------------------------- | ---------------------------------------------------------------------- |
| Модульных тестов                 | 576                                                                    |
| E2E-прогонов                     | 149 = 74 сценария × два проекта (1280 px и 375 px) + замер скорости    |
| Покрытие `src/core`              | 100 % строк при пороге 95 %                                            |
| Покрытие всего проверяемого кода | 96,8 %                                                                 |
| Начальный JS                     | ~256 КБ gzip при лимите плана 300 КБ                                   |
| Отдельные куски                  | графики 103 КБ, мастер импорта 12 КБ, ExcelJS 256 КБ — по требованию   |
| PDF финплана                     | pdfmake 346 КБ и шрифт Roboto 469 КБ — по нажатию, лежат в офлайн-кэше |
| 10 000 операций: «Бюджет»        | открывается за 69–122 мс при лимите 500 мс                             |
| 10 000 операций: «Обзор»         | пересчитывается за 67–79 мс при лимите 500 мс                          |

Размеры — из отчёта сборки Vite (`gzip:`); сторонний `gzip -c` даёт на пару
килобайт меньше из-за другого уровня сжатия.

Скорость меряет `e2e/performance.spec.ts`: три года операций заходят через
резервную копию, время идёт внутри страницы от нажатия до кадра с результатом,
пять замеров, в лимит должен уложиться самый долгий. Проект `performance`
запускается после остальных, чтобы не мерить загруженную машину. Цифры выше —
с машины разработки; с замедлением процессора в 4 раза (DevTools) самые долгие
замеры были 424 мс у «Бюджета» (первое открытие) и 300 мс у «Обзора».
